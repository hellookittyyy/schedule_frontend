# Schedule Frontend

Фронтенд системи складання розкладу. Статичні HTML/CSS/JS-сторінки, розміщені в корені сервера (без підшляху).
Дизайн: Mosaic. Опис компонентів і токенів: [`docs/design-system.md`](docs/design-system.md), живий довідник: [`design/system.html`](design/system.html).

---
## Публічна сторінка

| Назва сторінки | Опис | URL |
| :--- | :--- | :--- |
| **Розклад** | Публічний перегляд розкладу. Параметри `?g=<група>` та `?t=<викладач>` одразу відкривають розклад групи або викладача. | `/` |

## Локальний запуск

```bash
py scripts/dev-server.py
```

Далі відкрити `http://localhost:5500/`. Цей сервер забороняє браузеру кешувати файли, тож після змін завжди видно актуальну версію (на відміну від `py -m http.server`). Якщо порт 5500 зайнятий, сервер не стартує: зупини інший сервер або вкажи порт, наприклад `py scripts/dev-server.py 5502`.

## Версії CSS/JS (`?v=`)

Кожне підключення локального CSS/JS у сторінках має хеш вмісту файлу (`/assets/js/ui.js?v=ec4d50f9`). Коли файл змінюється, змінюється й адреса, тож після деплою браузер не візьме старий файл з кешу.

Після зміни будь-якого `.css` / `.js` і перед комітом:

```bash
py scripts/version-assets.py
```

Перевірка без змін: `py scripts/version-assets.py --check`. Щоб git сам не пропускав коміт із застарілими хешами, один раз на клон увімкни хук:

```bash
git config core.hooksPath .githooks
```
