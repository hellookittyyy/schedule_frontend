# Тест-кейси та чеклісти (простою мовою)

Цей документ для ручної перевірки системи розкладу в браузері: що натиснути і що має статися.
Технічна версія для розробки лежить у [`regression-checklist.md`](regression-checklist.md); цей файл її не замінює, а пояснює те саме людською мовою.

---

## 1. Як запустити проєкт

Потрібні два вікна PowerShell (два сервери працюють одночасно).

**Вікно 1: бекенд (дані, API)**

```powershell
cd D:\projects\course_work_schedule\schedule_backend
.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

**Вікно 2: фронтенд (сторінки)**

```powershell
cd D:\projects\course_work_schedule\schedule_frontend
py scripts/dev-server.py
```

Після цього відкрий у браузері:

| Що | Адреса |
|---|---|
| Публічний розклад (для студентів) | http://localhost:5500/ |
| Адмін-панель | http://localhost:5500/admin/ |
| API (сирі дані, для перевірки) | http://127.0.0.1:8000/api/ |

Зупинити сервер: у його вікні натиснути `Ctrl + C`.

### Перед тестами, які щось видаляють

Деякі кейси видаляють записи або перегенеровують розклад. Спершу зроби копію бази, щоб усе можна було повернути:

```powershell
Copy-Item D:\projects\course_work_schedule\schedule_backend\db.sqlite3 "D:\projects\course_work_schedule\db.sqlite3.bak-$(Get-Date -Format yyyy-MM-dd)-before-testing"
```

Повернути: зупинити бекенд, скопіювати файл назад під імʼям `db.sqlite3`, запустити бекенд знову.

## 2. Як цим користуватися

**Відмічати зручніше в інтерактивному чеклісті:** http://localhost:5500/docs/test-checklist.html (або просто відкрий файл `docs/test-checklist.html` у браузері). Там ті самі перевірки з кнопками «Ок / Не ок / Пропустити», коментарями і вкладкою «Баги» з формою за шаблоном із розділу 8. Відмітки зберігаються в браузері самі; «Зберегти копію (файл)» робить резервну копію.
Якщо змінюєш перевірки в цьому файлі, онови чекліст: `py scripts/build-test-checklist.py`.

- Кожен кейс: **що робиш** → **що має статися**. Якщо сталося саме так, став `[x]`.
- Якщо щось пішло не так, не виправляй одразу: запиши за шаблоном у розділі 8 (номер кейсу, що зробила, що побачила).
- Тримай відкритою консоль браузера (`F12` → вкладка **Console**). Червоні рядки там = помилка, навіть якщо на сторінці все виглядає нормально.
- Позначки: ⚠️ кейс змінює або видаляє дані (спершу копія бази).

### Словничок

| Слово в документі | Що це на екрані |
|---|---|
| Бокове меню | Ліва панель з пунктами «Головна», «Задачі», «Семестр» тощо |
| Список і картка | Більшість розділів: зліва список записів, справа картка вибраного запису з полями |

| Автозбереження | Кнопки «Зберегти» немає: зміна зберігається сама, коли виходиш з поля (клік деінде або `Tab`). Біля поля видно «Зберігаю…» → «Збережено» |
| Сповіщення | Маленьке віконце в куті екрана: «Збережено», помилка, або дія «Скасувати / Повернути» |
| Підтвердження в рядку | Замість вікна «Ви впевнені?» прямо на місці зʼявляються кнопки «Видалити» / «Скасувати» |
| Бічна панель | Панель, що виїжджає збоку (деталі пари, день календаря). Закривається `Esc` або кліком по затемненому фону |
| Блокер | Проблема, через яку розклад згенерувати не можна (наприклад, у плані немає викладача) |

## 3. Швидкий чекліст (10 хвилин)

Прогнати першим. Якщо тут щось не так, детальні кейси нема сенсу проходити.

- [ ] Обидва сервери запущені, у вікнах PowerShell немає червоних помилок
- [ ] http://127.0.0.1:8000/api/ відкривається і показує список посилань
- [ ] http://localhost:5500/admin/ відкривається, видно картку семестру і цифри ресурсів
- [ ] Клік по кожному пункту бокового меню відкриває сторінку без помилок (11 пунктів)
- [ ] У «Викладачах» видно список викладачів (не порожньо)
- [ ] У «Розкладі» адмінки після вибору семестру видно пари в сітці
- [ ] На http://localhost:5500/ пошук «ФЕІ-21» знаходить групу і показує її пари
- [ ] Перемикач теми (світла/темна) працює, після перезавантаження тема лишається
- [ ] У консолі браузера (`F12`) немає червоних помилок на жодній з цих сторінок

## 6. Звʼязані сценарії (від початку до кінця)

Ці кейси перевіряють, що розділи працюють разом, а не кожен окремо. ⚠️ Усі змінюють дані: зроби копію бази.

**Сценарій А. Новий предмет доходить до розкладу**

- [ ] 1. «Предмети»: створи «Тестовий предмет»
- [ ] 2. «Викладачі»: додай його викладачу «Викладач 1»
- [ ] 3. «Навчальні плани»: групі ФЕІ-21 додай рядок з цим предметом і викладачем, 2 пари
- [ ] 4. «Задачі» / «Семестр → Передперевірка»: блокерів не додалось
- [ ] 5. «Розклад»: «Згенерувати»
- [ ] 6. Публічна сторінка, ФЕІ-21: «Тестовий предмет» зʼявився в розкладі

**Сценарій Б. Обмеження впливає на генерацію**

- [ ] 1. «Обмеження»: «Викладач 1» має вихідний у понеділок
- [ ] 2. «Розклад»: «Згенерувати»
- [ ] 3. Фільтр «Викладач» → «Викладач 1»: жодної пари в понеділок

**Сценарій В. Проблема видна в «Задачах» і зникає після виправлення**

- [ ] 1. «Предмети»: створи предмет без викладача
- [ ] 2. Додай його в план групи (без можливості вибрати викладача або з порожнім)
- [ ] 3. «Задачі»: зʼявилась задача про цей предмет/план
- [ ] 4. Виправ просто в «Задачах» (призначити викладача): задача зникла, відсоток готовності виріс
